# Breakout Design

## Goal

Build Game 3 as a separate Godot project where the player moves a paddle, bounces a ball, clears a small block layout, loses if the ball leaves the bottom of the screen, and can restart after win or loss.

## Approaches Considered

Recommended approach: use simple `CharacterBody2D` scripts and manual collision response. This keeps the ball bounce predictable, makes collision handling readable, and fits the Games 1-3 guidance that direct local scripts are acceptable.

Alternative approach: use `RigidBody2D` physics for the ball. This is more physically realistic, but harder to control for a first Breakout implementation and more likely to create confusing edge cases.

Alternative approach: build one scene with all blocks manually authored. This is visually straightforward, but misses the Game 3 learning goal of reusable scenes and groups.

## Architecture

`Main.tscn` owns the block layout, win/loss state, UI labels, and restart. `Paddle.tscn` is a `CharacterBody2D` controlled with left/right input and clamped to the viewport. `Ball.tscn` is a `CharacterBody2D` that uses `move_and_collide()` and bounces off the paddle, walls, ceiling, and blocks. `Block.tscn` is a reusable `StaticBody2D` in the `blocks` group that disappears when hit.

The project uses primitive `ColorRect` visuals and rectangle collisions. The block grid is one short level generated by `Main` from exported constants. The game has no power-ups, no scoring beyond block count, no multiple levels, and no shared framework.

## Components

- `games/03-breakout/project.godot`: independent Godot project with input map and main scene.
- `games/03-breakout/scenes/Main.tscn`: root scene, paddle and ball instances, UI labels, and generated blocks.
- `games/03-breakout/scenes/Paddle.tscn`: player-controlled paddle body.
- `games/03-breakout/scenes/Ball.tscn`: moving ball body with bounce logic.
- `games/03-breakout/scenes/Block.tscn`: reusable breakable block.
- `games/03-breakout/scripts/main.gd`: block spawning, win/loss state, restart, UI.
- `games/03-breakout/scripts/paddle.gd`: horizontal movement and viewport clamp.
- `games/03-breakout/scripts/ball.gd`: ball movement, collision response, bottom-loss signal.
- `games/03-breakout/scripts/block.gd`: group registration and hit signal.

## Testing

Use Godot headless validation when available:

- `godot --headless --path games/03-breakout --editor --quit`
- `godot --headless --path games/03-breakout --quit-after 2`

Manual verification is required: launch the project, move the paddle, confirm the ball bounces, confirm blocks disappear, confirm clearing all blocks wins, confirm losing the ball loses, and confirm restart reloads the loop.
